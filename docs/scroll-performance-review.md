# LoopbackManager 滚动性能对照

后续状态：2026-10-29 已将产品升级并原位部署为 Azure 105、应用 `2.2609.6.0`，其中 #1066 包含本次候选的通用优化。
以下数值保留 Azure 104 与 Launcher 开发包的原始对照；没有重新测量或将这些数值归给正式 105 包。

2026-10-29，在同一台 RTX 4090 主机上，Launcher 的 Sprout 性能包在本次 LoopbackManager 分页滚动对照中降低了 GPU 占用。
两轮均值的平均值从 0.462% 降至 0.286%，约降低 38%；本次观测到的最大峰值从 4.482% 降至 2.621%。
这是本机固定脚本的结果，不能承诺所有鼠标滚轮操作都有相同比例的收益。

## 比较对象

- 基线：`0.1.0-rodel.104.1.g10d44ad338b7`，当前应用使用的完整 Azure 发布包。
- 候选：Launcher 当前冻结的 `0.1.0-launcher.junction.20261029.6` 本地包；来自 `richasy/launcher-performance-junction`。
  包的 repository commit 为 `3414f0a78a8a446b1708090465464257637cca44`，该开发版本同时承载打包时的未提交修改，
  因此以冻结包 SHA-256 确认被测字节，不能只用提交号重建它。
- 候选分支相对基线含 `a8782a405` 的通用失效/绘制修复、`bd4dfbb89` 的附加测量窗口绑定修复及合并提交。
  正在开发的根表面退休和 Direct2D 缓存阈值能力也在候选包中。

输入、构建和原始结果保留在忽略目录 `artifacts/scroll-performance/`：
`candidate-packages.json`、`candidate-cache-proof.json`、`build-proof.json`、`results-summary.json` 和各轮 `experiment.json`。
实际解析的七个 Sprout 运行依赖全部使用各自同一版本；候选 NuGet 缓存包与冻结副本逐个哈希一致。

## 测量方法

从本 worktree 的当前应用源文件生成两份隔离测试副本。两份副本的 C#、资源和图像文件哈希一致，
项目的差异为 Sprout 版本。两者均使用 NativeAOT、Debug 配置加 `Optimize=true`，并启用相同的画质与窗口配置。
Debug 在这里用于选择非打包设置存储，不能将结果直接当作已安装 Release 包的验收。

共同的测试宿主调整仅包括：使用独立程序集/设置名称、添加滚动区域的 AutomationId、去掉发布打包依赖。
没有改动产品的列表布局、内容、材质、分辨率、抗锯齿或帧率策略，也没有写入系统回环配置。
当前安装的产品仍使用 Azure 104，本次没有把开发包部署为产品版本。

使用性能分支编译的第一方 Sprout.DevTools，启动并持有精确进程，要求真实 GPU 样本、固定窗口条件和完成进程清理。
四轮均保持前台、可见、未最小化；客户端物理尺寸 `1530 × 1850`、DPI `240` 一致。
顺序为基线、候选、候选、基线，以检查先后顺序的影响。

每轮预热 3 秒、静息基线 4 秒、动作区间 20 秒、结束静息 3 秒，按 200 ms 采样。
动作脚本从顶部开始，执行 8 次 UIA LargeIncrement、8 次 LargeDecrement，命令间等待 400 ms；
动作区间也包含这些命令后的自然稳定时间。它是固定分页往返负载，不是物理鼠标滚轮或触控板惯性轨迹。
GPU 数值为精确 PID 的 PDH 最大引擎占用，不是整卡占用或所有引擎之和；P95 和峰值均依赖此采样周期。

## 有效结果

| 运行 | GPU 均值 | GPU P95 | GPU 峰值 |
| --- | ---: | ---: | ---: |
| baseline-pages-a | 0.496% | 2.226% | 4.482% |
| candidate-pages-a | 0.381% | 1.954% | 2.621% |
| candidate-pages-b | 0.190% | 0.795% | 1.725% |
| baseline-pages-b | 0.428% | 2.085% | 3.396% |

每轮动作区间有 100 个有效 GPU 样本，四轮结果和精确进程清理均为 passed。
四轮结束后的静息区间均值/峰值均为 0%。初始基线中仅第一轮有短暂活动，其均值 0.034%、峰值 0.673%；其余为 0%。
普通空闲本来已接近零，主要收益出现在交互区间。

另用第一方 UIA/WGC 分别启动并查看两份程序，列表内容、布局、图标和文字外观一致；
证据为 `baseline-visual/window.png`、`candidate-visual/window.png` 和对应 UIA 树。
两张静态起始画面的 PNG 字节完全一致，SHA-256 均为
`BA20D1DA038956B947794C62927FF95E51F3529B85B71695659E6EDEBF6148BB`。
早期前台变化、脚本预检及旧工具动作时间窗校验失败的轮次全部排除，没有用其局部样本拼接结果。

## 源码关联与采用范围

| 优化 | 对本应用的关系 |
| --- | --- |
| 内部指针观察不再自动请求绘制 | 通用收益，减少鼠标移动时没有可见状态变化的额外帧；公共指针事件的绘制契约保留。 |
| root slice 分别追踪主内容和标题栏损伤 | 可以减少列表交互连带重绘的静态区域，是本应用相关的通用优化。 |
| 原生 Acrylic 控件保留内在 promotion、可记录 presenter | 对使用这些控件的应用更直接；当前列表没有 Launcher 自定义材质 surface。 |
| 方角阴影的内部裁剪 | 当前卡片没有声明阴影，不能把它认定为此次列表收益的主要来源。 |
| 地图图钉、皮肤渲染线程和 Launcher 应用层缓存 | 属于 Launcher 代码，没有进入本次 LoopbackManager 对照。 |
| Direct2D 64 MiB 缓存阈值 | 本应用继续使用默认 `UseD2DBackend()`，没有设置该可选阈值；它针对缓存/显存，不是保证降低滚动 GPU 的开关。 |

这次比较的是整批框架包，没有分别关闭各项优化，因而不能把 38% 的差值归因给某一个改动。
两轮候选都低于两轮基线，但样本规模不足以建立通用性能保证；还应验证物理滚轮、触控板、其他 DPI 和已安装包。
本轮没有采集逐帧时序或输入延迟，不据此宣称帧率或响应延迟改善。

这些通用修复值得在 Sprout 正式发布后让 LoopbackManager 跟进。本次没有修改 Launcher/Sprout 正在开发的工作树，
也没有合并或发布它们的未提交内容。
